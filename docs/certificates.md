# 证书（Let's Encrypt）

既然域名已经在管，证书也在这里签：用 **DNS-01** 挑战走已有的 DNSPod 账号，
容器不需要对外暴露任何端口，通配符证书同样支持。签发与续期都在后端完成，
前端只负责配置和看结果。

## 使用

1. `docker-compose.yml` 已经挂了 `./certs:/certs`；其他 TLS 应用只读挂同一个主机
   目录即可（nginx 那侧加一行 `- ./certs:/certs:ro`），两个容器之间不需要互通。
2. 在「Certificates」页新建一条：名称（决定子目录名）、域名（一行一个，通配符写
   `*.example.com`）、回答挑战用的 DNSPod 账号、密钥类型（默认 ECDSA P-256，另有
   P-384 / RSA 2048 / RSA 4096）与输出子目录。
3. 点「Renew now」立即签发。打开自动续期后：每天 `acme.check_hour`（默认 03:00）
   检查一次，**启动约 1 分钟后还会补查一次**（避免停机正好错过那一刻）；剩余天数进入
   `acme.renew_before_days`（默认 30）的会重新签发，**还没签发过的也会去签**--
   "建好、打开自动续期、然后不管"就是预期用法；结果走通知渠道。设为 0 则只剩按钮。
   同时最多签发两张，其余排队（列表里同样显示 RUNNING，只是轮到自己前不动）。
   排队的时间也算在 `acme.timeout` 里：等过头的会记一次失败（消息为 ran out of
   time before it could start）并发通知，下一次检查再试。

## 文件

```
/certs/<名称>/
  cert.pem        # 叶子证书
  chain.pem       # 中间证书
  fullchain.pem   # 叶子 + 中间证书，TLS 应用通常用这个
  privkey.pem     # PKCS#8 私钥，默认 0600
```

命名与 certbot 一致，所以按 certbot 写好的配置不用改。每次写入都是「同目录临时文件 +
rename」，读取方要么看到旧证书要么看到新证书，不会读到半个文件，因此续期时不需要停
nginx。

## 权限

- 私钥默认 `0600`，属主是容器内的 root--podman rootless 下就是运行它的你（rootful
  docker 下则是宿主机上的 root，uid 0），所以保持默认即可。只有当读取方**不是**同一个用户时才需要处理：把 `acme.key_mode` 设成 `0640`，
  并在宿主机给目录设 setgid 让新文件带上共享组；或者两边统一用 `--user` 指定同一个 uid。
- 私钥不经过 API：接口只返回路径和到期时间，页面上没有任何地方能读到密钥内容。

## 注意事项

- 改证书名会把默认输出目录一起换走：已写出的文件留在原地，下一次签发写到新目录。
  创建与更新都会拒绝两张证书共用同一输出目录的组合（后签发的会覆盖先签发的证书与
  私钥）--本版本之前已存在的此类行，在改掉目录或名字之前任何更新都会被拒绝。

- **先在 staging 上试**：把 `acme.directory` 指向
  `https://acme-staging-v02.api.letsencrypt.org/directory`，签出来的是不受信任的证书，
  但没有生产环境那套速率限制。
- **切换目录等于换账号**：ACME 账号密钥按 `directory` 分开保存，从 staging 切回生产会
  注册一个新账号；staging 签出的证书不受信任，切回去之后记得在页面上重新签发一次。
- `acme.email` 只在账号**首次注册**时生效，之后改它不会更新 CA 侧的联系方式。
- `acme.enabled=false` 时页面会说明原因并禁用签发入口（证书、路径、到期照常显示），
  服务端对任何签发请求仍返回 503--直接调 API 或停留在旧页面上都不会误触发。
- ACME 账号密钥（ECDSA P-256）加密存在 `acme_accounts` 表里，随 `data/` 一起备份；
  丢了只能重新注册成新账号（已签发的证书仍然有效，只是不再受该账号管理）。
- 删除一条证书只删记录，磁盘上的文件保持原样--我们并不知道还有谁在用它。
- 新证书要不要让网关重新加载，由你在那一侧决定（例如定时 reload）；本项目不执行
  远程命令。
